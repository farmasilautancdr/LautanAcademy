# i18n Phase 2 — Batch 3 (Warehouse + Area Manager group) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Migrate the Warehouse + Area Manager group — `WarehouseManagerDashboard.vue`, `WarehouseManagerResultsView.vue`, `WarehouseManagerStaffView.vue`, `AreaManagerDashboard.vue`, `AreaManagerReviewsView.vue` — to `vue-i18n`, with real EN and BM text for every string in scope. `WarehouseManagerStaffView.vue`'s embedded `ManageStaffPanel` was already migrated in Phase 2 Batch 2 (as a side effect of Outlet Manager's own Manage Staff page) — nothing further needed there beyond this batch's own page chrome.

**Architecture:** Same as Phase 1/Batch 1/Batch 2 — `useI18n()` (Composition API) per component, one top-level namespace per view added to the existing `src/i18n/locales/{en,ms}.json`.

**Tech Stack:** Vue 3 (Composition API, `<script setup>`), `vue-i18n` (already installed/registered), existing Tailwind tokens. No test runner exists in this project — verification is `npm run build` plus manual click-through.

## Global Constraints

- No new libraries (CLAUDE.md: no new frameworks/libs without asking — `vue-i18n` already approved, nothing new needed here).
- BM text is authored directly (not machine-translated via a paid API) — spot-check by a native speaker recommended afterward, still outstanding.
- Match existing file conventions: `<script setup>`, Tailwind utility classes inline, no scoped CSS.
- Bilingual EN/MS parity: every key added to `en.json` must have a matching key in `ms.json` in the same task — never land a task with an English-only key.
- Brand name "Lautan Academy" is never translated.
- Dynamic/DB-sourced values (staff names, outlet codes, topic labels typed by the manager, dates as rendered by `toLocaleDateString`, category/subcategory names) are **not** translated — only static UI chrome (labels, buttons, headings, error messages, `confirm()` dialog text) gets a translation key.
- Reuse existing keys instead of duplicating where the exact same concept already has one — `WarehouseManagerDashboard.vue`/`WarehouseManagerResultsView.vue`/`WarehouseManagerStaffView.vue`'s "Warehouse Manager" header label reuses Phase 1's `sidebar.roleWarehouseManager` key (same pattern Batch 1/2 established for Outlet Manager).
- **Area Manager header is different from Outlet/Warehouse Manager and is deliberately NOT touched**: the eyebrow line shows `{{ managerLabel }}`, which is real session data (`auth.manager.label`, e.g. `"R2 - HAZWANI"` — the actual area identity set at login), not a static role literal like "Outlet Manager"/"Warehouse Manager" — so there's no hardcoded chrome string there to translate. Its `|| 'Area Manager'` fallback (only reachable if `label` is ever empty, which the real login flow never produces) is left as an English-only edge-case default rather than reworking `managerLabel` into a reactive computed just for a practically-unreachable path — an accepted, flagged gap, not an oversight.
- `confirm()` dialog strings (native browser dialogs) are still translated via `t()` — same treatment as any other static string.
- The client-computed `skillLevel` badge (`'HIGH' | 'MEDIUM' | 'LOW'`) in `AreaManagerReviewsView.vue` is **not** translated — it's the exact literal value submitted to and stored in the backend (`reports.Skill Level`), matching GAS's original enum; translating only the on-screen preview would desync it from what gets persisted and from other views (e.g. Batch 2's `OutletManagerStaffReviewView.vue`) that display the same DB field verbatim.
- `v-for` loop variables named `t` collide with the i18n `t()` function once `useI18n()` is destructured in a component — rename those specific loop variables to `t2` (same fix already applied in Batch 1/Batch 2), not a rename of `t()` itself.

Replace the countdown's `'Expired'` literal inside `startCountdown()`:

```js
function startCountdown() {
  if (timerHandle) clearInterval(timerHandle)
  const tick = () => {
    if (!activeQuiz.value) { remaining.value = ''; return }
    const expiresAt = new Date(activeQuiz.value.createdAt).getTime() + 60 * 60 * 1000
    const ms = expiresAt - Date.now()
    if (ms <= 0) { remaining.value = t('warehouseManagerDashboard.expired'); activeQuiz.value = null; return }
    const mins = Math.floor(ms / 60000)
    const secs = Math.floor((ms % 60000) / 1000)
    remaining.value = `${mins}:${secs.toString().padStart(2, '0')}`
  }
  tick()
  timerHandle = setInterval(tick, 1000)
}
```

Replace the `createQuiz()` error strings:

```js
async function createQuiz() {
  createError.value = ''
  if (!topicLabel.value.trim()) {
    createError.value = t('warehouseManagerDashboard.errorEnterTopic')
    return
  }
  creating.value = true
  try {
    const data = await api.createAiQuiz({
      outlet: location,
      sourceType: resourceSource.value ? 'resource' : 'topic',
      sourceValue: resourceSource.value || topicLabel.value.trim(),
      topicLabel: topicLabel.value.trim(),
      count: count.value,
      extraNotes: extraNotes.value.trim(),
      manager: managerLabel,
    })
    activeQuiz.value = data
    startCountdown()
    topicLabel.value = ''
    extraNotes.value = ''
    clearResourceSource()
  } catch (err) {
    createError.value = err.message || t('warehouseManagerDashboard.errorGenerateFailed')
  } finally {
    creating.value = false
  }
}
```

Replace the `confirm()` call inside `endQuiz()`:

```js
async function endQuiz() {
  if (!confirm(t('warehouseManagerDashboard.confirmEndQuiz'))) return
  try {
    await api.endQuiz(location)
  } catch (e) { /* best-effort */ }
  if (timerHandle) clearInterval(timerHandle)
  activeQuiz.value = null
}
```

```js
async function submitReport() {
  formError.value = ''
  formNotice.value = ''
  if (!formOutlet.value || !formStaff.value || !formTopic.value || !selectedResult.value) {
    formError.value = t('areaManagerReviewsView.errorPickFields')
    return
  }
  if (competency.value !== '' && (isNaN(competency.value) || competency.value < 0 || competency.value > 10)) {
    formError.value = t('areaManagerReviewsView.errorCompetencyRange')
    return
  }
  submitting.value = true
  try {
    const data = await api.saveReport({
      outlet: formOutlet.value,
      staffName: formStaff.value,
      topic: formTopic.value,
      manager: managerLabel,
      quizScore: selectedResult.value.Percentage,
      skillLevel: skillLevel.value,
      competency: competency.value,
      gaps: gaps.value,
      rec: rec.value,
      productKnowledgeComments: productKnowledgeComments.value,
      isEdit: isEdit.value,
    })
    if (data.status === 'duplicate') {
      const who = data.existing?.manager || t('areaManagerReviewsView.anotherManager')
      const when = data.existing?.timestamp ? new Date(data.existing.timestamp).toLocaleDateString() : ''
      formNotice.value = when
        ? t('areaManagerReviewsView.duplicateNoticeWithDate', { who, when })
        : t('areaManagerReviewsView.duplicateNotice', { who })
      return
    }
    if (data.status === 'auth_error') {
      formError.value = t('areaManagerReviewsView.authError')
      return
    }
    resetForm()
    await loadAll()
  } catch (err) {
    formError.value = err.message || t('areaManagerReviewsView.errorSaveFailed')
  } finally {
    submitting.value = false
  }
}
```
