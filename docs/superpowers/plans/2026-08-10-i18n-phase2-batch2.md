# i18n Phase 2 — Batch 2 (Outlet Manager group) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Migrate the Outlet Manager group — `OutletManagerDashboard.vue`, `OutletManagerResultsView.vue`, `OutletManagerStaffView.vue`, `OutletManagerStaffReviewView.vue`, and the shared `ManageStaffPanel.vue` component — to `vue-i18n`, with real EN and BM text for every string in scope. `ManageStaffPanel.vue` is also used by `WarehouseManagerDashboard.vue`, so migrating it here incidentally i18n-izes that usage too, though `WarehouseManagerDashboard.vue` itself stays out of scope for this batch (planned in Batch 3).

**Architecture:** Same as Phase 1/Batch 1 — `useI18n()` (Composition API) per component, one top-level namespace per view added to the existing `src/i18n/locales/{en,ms}.json`. `ManageStaffPanel.vue` gets its own `manageStaffPanel` namespace since it's a component, not a view, but follows the identical pattern.

**Tech Stack:** Vue 3 (Composition API, `<script setup>`), `vue-i18n` (already installed/registered), existing Tailwind tokens. No test runner exists in this project — verification is `npm run build` plus manual click-through.

## Global Constraints

- No new libraries (CLAUDE.md: no new frameworks/libs without asking — `vue-i18n` already approved, nothing new needed here).
- BM text is authored directly (not machine-translated via a paid API) — spot-check by a native speaker recommended afterward, still outstanding.
- Match existing file conventions: `<script setup>`, Tailwind utility classes inline, no scoped CSS.
- Bilingual EN/MS parity: every key added to `en.json` must have a matching key in `ms.json` in the same task — never land a task with an English-only key.
- Brand name "Lautan Academy" is never translated.
- Dynamic/DB-sourced values (staff names, outlet codes, topic labels typed by the manager, dates as rendered by `toLocaleDateString`, category/subcategory names) are **not** translated — only static UI chrome (labels, buttons, headings, error messages, `confirm()` dialog text) gets a translation key.
- Reuse existing keys instead of duplicating where the exact same concept already has one — all four "Outlet Manager" header labels in this batch reuse Phase 1's `sidebar.roleOutletManager` key instead of a new literal per view (same pattern `ResourcesView.vue` established in Batch 1).
- `confirm()` dialog strings (native browser dialogs) are still translated via `t()` — same treatment as any other static string, `window.confirm(t(...))`.

Replace the countdown's `'Expired'` literal inside `startCountdown()`:

```js
function startCountdown() {
  if (timerHandle) clearInterval(timerHandle)
  const tick = () => {
    if (!activeQuiz.value) { remaining.value = ''; return }
    const expiresAt = new Date(activeQuiz.value.createdAt).getTime() + 60 * 60 * 1000
    const ms = expiresAt - Date.now()
    if (ms <= 0) { remaining.value = t('outletManagerDashboard.expired'); activeQuiz.value = null; return }
    const mins = Math.floor(ms / 60000)
    const secs = Math.floor((ms % 60000) / 1000)
    remaining.value = `${mins}:${secs.toString().padStart(2, '0')}`
  }
  tick()
  timerHandle = setInterval(tick, 1000)
}
```

Replace the `createQuiz()` error strings:

```js
async function createQuiz() {
  createError.value = ''
  if (!topicLabel.value.trim()) {
    createError.value = t('outletManagerDashboard.errorEnterTopic')
    return
  }
  creating.value = true
  try {
    const data = await api.createAiQuiz({
      outlet,
      sourceType: resourceSource.value ? 'resource' : 'topic',
      sourceValue: resourceSource.value || topicLabel.value.trim(),
      topicLabel: topicLabel.value.trim(),
      count: count.value,
      extraNotes: extraNotes.value.trim(),
      manager: managerLabel,
    })
    activeQuiz.value = data
    startCountdown()
    topicLabel.value = ''
    extraNotes.value = ''
    clearResourceSource()
  } catch (err) {
    createError.value = err.message || t('outletManagerDashboard.errorGenerateFailed')
  } finally {
    creating.value = false
  }
}
```

Replace the `confirm()` call inside `endQuiz()`:

```js
async function endQuiz() {
  if (!confirm(t('outletManagerDashboard.confirmEndQuiz'))) return
  try {
    await api.endQuiz(outlet)
  } catch (e) { /* best-effort */ }
  if (timerHandle) clearInterval(timerHandle)
  activeQuiz.value = null
}
```

`managerLabel` (`` `Outlet Manager - ${outlet}` ``, sent to the backend as an audit-trail string) stays exactly as-is — it's data written to the DB, not UI chrome, out of scope per the Global Constraints.

  if (!name || !/^\d{4}$/.test(addPin.value.trim())) {

    addPin.value = ''
    await load()
  } catch (err) {
    addError.value = err.message || t('manageStaffPanel.errorAddFailed')
  } finally {
    adding.value = false
  }
}
