# i18n Phase 2 — Batch 4 (Supervisor group) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Migrate the Supervisor group — `SupervisorDashboard.vue` (Company-wide activity), `SupervisorAddResourcesView.vue` (Add Resources), `SupervisorReportsView.vue` (Cluster Reports), `SupervisorStaffComparisonView.vue` (Staff Comparison), `SupervisorManagerAccessView.vue` (Manager Access) — to `vue-i18n`, with real EN and BM text for every string in scope. This is the last group in Phase 2 — after this batch, all 32 views/components in the original i18n spec are migrated. `SupervisorLoginView.vue` is already done (Phase 1, standalone login screens) and is out of scope here.

**Architecture:** Same as Phase 1/Batch 1/2/3 — `useI18n()` (Composition API) per component, one top-level namespace per view added to the existing `src/i18n/locales/{en,ms}.json`.

**Tech Stack:** Vue 3 (Composition API, `<script setup>`), `vue-i18n` (already installed/registered), existing Tailwind tokens. No test runner exists in this project — verification is `npm run build` plus manual click-through.

## Global Constraints

- No new libraries (CLAUDE.md: no new frameworks/libs without asking — `vue-i18n` already approved, nothing new needed here).
- BM text is authored directly (not machine-translated via a paid API) — spot-check by a native speaker recommended afterward, still outstanding.
- Match existing file conventions: `<script setup>`, Tailwind utility classes inline, no scoped CSS.
- Bilingual EN/MS parity: every key added to `en.json` must have a matching key in `ms.json` in the same task — never land a task with an English-only key.
- Brand name "Lautan Academy" is never translated.
- Dynamic/DB-sourced values (staff names, outlet codes, topic labels, dates via `toLocaleDateString`) are **not** translated — only static UI chrome gets a translation key.
- Header eyebrow ("Supervisor") is a static literal in all 5 views here (unlike Batch 3's Area Manager, which showed real session data instead) — reuses Phase 1's `sidebar.roleSupervisor` key, same pattern as Outlet/Warehouse Manager in Batch 2/3.
- `confirm()` dialog strings are still translated via `t()`.
- `SupervisorDashboard.vue`'s per-row `kind` tag (`'Standard'` / `'AI Practice'`) is a client-only display label — never sent to the backend or persisted — so unlike Batch 3's `skillLevel` enum (which IS persisted and left untranslated), this one gets translated (`supervisorDashboard.kindStandard` / `kindAiPractice`), computed reactively so it updates on language switch.
- `SupervisorReportsView.vue`'s CSV export (`CSV_COLUMNS` header row) is a downloadable data artifact, not on-screen UI chrome — deliberately left in English regardless of UI language, consistent with keeping exported/persisted data formats stable (same reasoning as Batch 3's `skillLevel` decision, applied to a different kind of "not really UI text" value).
- `SupervisorStaffComparisonView.vue`'s "N attempt(s)" count reuses the vue-i18n pluralization pattern established in Phase 2 Batch 1: `en.json` uses pipe syntax (`"{count} attempt | {count} attempts"`, picked by `t(key, count)`), `ms.json` uses a single non-inflected form (BM doesn't pluralize).
- `SupervisorManagerAccessView.vue`'s three role labels ("Outlet Manager"/"Warehouse Manager"/"Area Manager") reuse Phase 1's `sidebar.roleOutletManager`/`roleWarehouseManager`/`roleAreaManager` keys instead of new literals — same reuse pattern Batch 2/3 established, applied here via a `labelKey` field on the `ROLES` array instead of a hardcoded `label` string.

import { useI18n } from 'vue-i18n'

import { AREAS, outletsForArea } from '../config/areas'

const { t } = useI18n()
const windowMonths = ref(3) // matches GAS's default — fast first load
const loading = ref(true)

const aiResults = ref([])
const regionFilter = ref('ALL')
const outletFilter = ref('ALL')

```js
const scopedActivity = computed(() => {
  const tagged = [
    ...results.value.map(r => ({ ...r, kind: t('supervisorDashboard.kindStandard') })),
    ...aiResults.value.map(r => ({ ...r, kind: t('supervisorDashboard.kindAiPractice') })),
  ]
  let list = tagged
  if (regionFilter.value !== 'ALL') {
    const regionOutlets = new Set(outletsForArea(regionFilter.value))
    list = list.filter(r => regionOutlets.has(r.Outlet))
  }
  if (outletFilter.value !== 'ALL') list = list.filter(r => r.Outlet === outletFilter.value)
  return list
})
```

import { ref, computed } from 'vue'

```js
async function handleFileSelect(e) {
  const file = e.target.files[0]
  if (!file) return
  cError.value = ''
  cUploading.value = true
  try {
    const data = await api.uploadContentFile(file)
    cLink.value = data.url
    cUploadedName.value = file.name
  } catch (err) {
    cError.value = err.message || t('supervisorAddResourcesView.errorUploadFailed')
    if (cFileInput.value) cFileInput.value.value = ''
  } finally {
    cUploading.value = false
  }
}

async function addContent() {
  cError.value = ''
  if (!cTopic.value.trim() || !cCategory.value.trim() || !cTitle.value.trim() || !cBody.value.trim()) {
    cError.value = t('supervisorAddResourcesView.errorRequiredFields')
    return
  }
  cSaving.value = true
  try {
    await api.addContent({ topic: cTopic.value.trim(), category: cCategory.value, title: cTitle.value.trim(), body: cBody.value.trim(), link: cLink.value.trim() })
    cTopic.value = ''
    cTitle.value = ''
    cBody.value = ''
    cLink.value = ''
    cUploadedName.value = ''
    if (cFileInput.value) cFileInput.value.value = ''
    await loadContent()
  } catch (err) {
    cError.value = err.message || t('supervisorAddResourcesView.errorSaveFailed')
  } finally {
    cSaving.value = false
  }
}

async function removeContent(item) {
  if (!confirm(t('supervisorAddResourcesView.confirmRemove', { title: item.Title }))) return
  try {
    await api.deleteContent(item.ID)
    await loadContent()
  } catch (e) { /* best-effort */ }
}
```

- [ ] **Step 3: Update the script block**

```js
import { ref } from 'vue'
import { useI18n } from 'vue-i18n'
import { api } from '../api/client'
import PasswordField from '../components/PasswordField.vue'

const { t } = useI18n()

const ROLES = [
  { role: 'outlet_manager', labelKey: 'sidebar.roleOutletManager' },
  { role: 'warehouse_manager', labelKey: 'sidebar.roleWarehouseManager' },
  { role: 'area_manager', labelKey: 'sidebar.roleAreaManager' },
]

const pins = ref({ outlet_manager: '', warehouse_manager: '', area_manager: '' })
const confirmPins = ref({ outlet_manager: '', warehouse_manager: '', area_manager: '' })
const saving = ref({ outlet_manager: false, warehouse_manager: false, area_manager: false })
const status = ref({ outlet_manager: '', warehouse_manager: '', area_manager: '' })
const statusOk = ref({ outlet_manager: false, warehouse_manager: false, area_manager: false })

async function rotate(role) {
  status.value[role] = ''
  statusOk.value[role] = false
  const newMasterPin = pins.value[role].trim()
  const confirmMasterPin = confirmPins.value[role].trim()
  if (!newMasterPin) {
    status.value[role] = t('supervisorManagerAccessView.errorEnterPin')
    return
  }
  if (newMasterPin !== confirmMasterPin) {
    status.value[role] = t('supervisorManagerAccessView.errorPinsMismatch')
    return
  }
  saving.value[role] = true
  try {
    const res = await api.rotateMasterPin({ role, newMasterPin })
    if (res.status !== 'ok') throw new Error(res.error || t('supervisorManagerAccessView.errorUpdateFailed'))
    pins.value[role] = ''
    confirmPins.value[role] = ''
    status.value[role] = t('supervisorManagerAccessView.successUpdated')
    statusOk.value[role] = true
  } catch (err) {
    status.value[role] = err.message || t('supervisorManagerAccessView.errorUpdateFailed')
    statusOk.value[role] = false
  } finally {
    saving.value[role] = false
  }
}
```
